1. จุดเริ่มต้นและวิสัยทัศน์ของระบบ (System Vision)

🕒 บันทึกเมื่อ: 17 กันยายน 2026 (10:00 น.)

ระบบถูกออกแบบขึ้นเพื่อบริหารกระบวนการผลิตสื่อตั้งแต่ต้นจนจบ (End-to-End Media Pipeline):

Media Production Pipeline:
Idea ➔ Planning ➔ Task Assignment ➔ Production ➔ Legal Check ➔ Review ➔ Revision ↺ ➔ Approval ➔ Schedule ➔ Publish ➔ Analytics

4 เสาหลักของระบบ (4 Core Pillars):

  1. Content Production Management: วงจรงานสร้างสรรค์, การแตก Task ย่อย, การตรวจงาน และคิวงาน
  2. Content Intelligence: เก็บสถิติ Performance จาก YouTube Data API v3 และ TikTok API
  3. Recommendation Engine: วิเคราะห์แนวโน้มเพื่อแนะนำหัวข้อและเวลาโพสต์ที่เหมาะสม
  4. Legal & Compliance Gatekeeper: ระบบ Checklist ตรวจสอบลิขสิทธิ์เพลง, PDPA, เครื่องหมายการค้า และกฎชุมชน 100% ก่อนเผยแพร่

Phase 1: Backend Foundation

สำเร็จ ✅
🕒 17 ก.ย. 2026 (10:30 - 18:30 น.)

1.1 เริ่มต้นด้วย Relational Database (PostgreSQL)

  • ออกแบบฐานข้อมูลแบบ Relational ในไฟล์ database/schema.sql
  • กำหนดตารางมาตรฐาน: users, user_role, team, content, task, legal_article
  • ติดตั้ง Express.js, เชื่อมต่อผ่านไลบรารี pg (Connection Pool)
  • สร้างระบบ JWT Authentication และ Middleware ตรวจสอบสิทธิ์ (RBAC: Admin, Manager, Member)

1.2 การปรับเปลี่ยนครั้งสำคัญ: สู่ MongoDB + Mongoose (NoSQL)

  • เปลี่ยนฐานข้อมูลเป็น MongoDB เพื่อความคล่องตัวในการเก็บข้อมูลมีเดียและ Time-series metrics
  • สร้าง Mongoose Models: User.js, Content.js, Task.js, Idea.js, Team.js, LegalArticle.js
  • สร้าง Seed Script (npm run seed) เพื่อจำลองข้อมูลทั้งระบบอัตโนมัติด้วยคำสั่งเดียว

Phase 14: สถาปัตยกรรม Team-Based Workspace & การยกเลิก Mock Data สู่ MongoDB 100%

สำเร็จ ✅
🕒 22 ก.ย. 2026 (14:45 - 15:45 น.)

ยกระดับระบบจากระบบจัดการงานส่วนบุคคล (Personal Tasks) สู่ "ระบบบริหารจัดการกระบวนการผลิตสื่อแบบทีม (Team-Based Content Production Workspace)" พร้อมทั้งตัด Mock Data ออกจาก State ในแอปพลิเคชัน 100% เชื่อมต่อฐานข้อมูล MongoDB จริงสมบูรณ์แบบ:

1. วิสัยทัศน์ Team Workspace Paradigm

  • สมาชิก (Member) และผู้จัดการ (Manager) เข้าถึงหน้า "ทีมของฉัน (Team Overview)"
  • แสดงงานทั้งหมดของทีม, ผู้รับผิดชอบ, สถานะงาน, หลอด Progress Bar รายชิ้นงานและภาพรวมทีม (0-100%), กำหนดส่งมอบ (Deadline)
  • แสดงสถานะการทำงานสดของเพื่อนร่วมทีม (กำลังทำงาน, รอตรวจ, ว่าง, ออฟไลน์)
  • มี Team Activity Feed บันทึกกิจกรรมสด เช่น John ส่งงานตรวจ, Jane แก้ไขสคริปต์, Manager สั่งแก้ พร้อมเวลาแบบ Real-time

2. นโยบายความปลอดภัยและขอบเขตสิทธิ์ (Team-Level Authorization Guard)

  • สร้าง Middleware verifyTeamAccess ป้องกันการดูข้อมูลข้ามทีม (403 Forbidden หากไม่ใช่สมาชิกทีม)
  • Member ดูภาพรวมและงานของทีมได้ แต่ แก้ไขได้เฉพาะงานที่ได้รับมอบหมายของตนเอง เท่านั้น
  • Manager สามารถตรวจงาน สั่งแก้ (Request Revision) อนุมัติ (Approve) และดูภาพรวมของทีมได้ครบถ้วน

3. นโยบาย Zero-Mock Policy (เชื่อมต่อ MongoDB 100%)

  • ถอด Mock Data ออกจาก State เริ่มต้นทั้งหมดใน ManagerDashboard.jsx, MemberTaskList.jsx, และ IdeaListScreen.jsx
  • แสดงผลข้อมูลสดที่ดึงมาจาก MongoDB ผ่าน Express REST API พร้อม Loading Spinner และ Empty State ที่ประณีต

4. การพัฒนา Backend & Database

  • สร้าง Mongoose Model: TeamActivity.js สำหรับบันทึกฟีดกิจกรรมของทีม
  • อัปเกรด Schema: เพิ่ม teamId, workingStatus ใน User.js, เพิ่ม teamId, progress ใน Content.js และ Task.js
  • พัฒนา REST Endpoints ครบชุดใน teams.routes.js (/api/teams/my-team, /api/teams/:teamId/dashboard, /activity, /tasks, /members)
  • อัปเกรด seed.js จำลองข้อมูล Team A ("Content Team A") และ Team B พร้อมงานและประวัติกิจกรรมครบถ้วน

5. การพัฒนา Mobile Application

  • เพิ่ม teamApi ใน src/services/api.js
  • สร้างคอมโพเนนต์ไอคอน 'team' ใน TabIcon.jsx
  • พัฒนาหน้าจอใหม่ TeamOverviewScreen.jsx พร้อม KPI Cards, Progress Bar, รายชื่อสมาชิก, และฟีดกิจกรรมพร้อม Pull-to-Refresh
  • จัดระเบียบแท็บนำทางใน MemberNavigator.jsx และ ManagerNavigator.jsx
